## 1. 背景与问题

### 1.1 业务背景

日常通过飞书电子表格管理达人合作：一作者可对应多条视频合作行，表中已有视频链接、视频 ID、播放量等字段。当前播放量依赖人工打开 TikTok 查看后回填，成本高、易漏更、难对比周环比。

### 1.2 核心问题

1. **播放量更新靠人工**，作者与视频规模扩大后不可持续。
2. **需要能排除少数不跟的视频**：默认表中所有有视频 ID 的行都要更新，只有主动取消才跳过。
3. **作者可配合授权，但不能保证长期有效**；过期时必须在表格上可见，而不是静默失败。

### 1.3 产品目标

在**尽量零成本**前提下，实现：

- 每周自动更新表中视频的播放量；电脑关机时调度仍能跑；随时可手动补跑。
- 走 TikTok 官方授权取数；写入值与官方接口返回一致。
- 授权过期或不配合时，在对应行标注「已过期」，不爬虫、不过验证码。

## 2. 用户与使用场景

### 2.1 用户画像

| 角色 | 描述 |
|------|------|
| 唯一用户（管理员） | 维护达人合作表、取消个别视频的追踪、处理授权过期后的重新授权 |

本期不做多角色权限、不做对外 SaaS。

### 2.2 核心场景

| ID | 场景 | 期望结果 |
|----|------|----------|
| S1 | 每周定期更新播放量 | 默认所有有视频 ID 的行被刷新；「播放量(K)」与更新时间写回 |
| S2 | 某条视频不再跟 | 该行「追踪」改为否后，后续周更跳过 |
| S3 | 作者完成 TikTok 授权 | 该作者名下视频走 API 自动取数，授权状态写「已授权」 |
| S4 | 授权过期 / 未授权 | 不更新播放量；该作者相关行「授权状态」写「已过期」或「未授权」 |
| S5 | 视频 ID 缺失 | 跳过并写同步状态，不阻塞其他行 |
| S6 | 电脑关机或想立刻看数 | 关机不耽误周更；需要时手动触发一次 |

## 3. 范围定义

### 3.1 In Scope（本期要做）

- 对接**现有飞书电子表格**（非多维表），在一张业务表上读写。
- 以**视频 ID** 为主键拉取播放量，写回「播放量(K)」。
- **默认全表追踪**（有视频 ID 即更新）；仅当该行主动标为不追踪时跳过。不做作者级总开关。
- **Plan A**：TikTok 开发者应用 + 作者授权取数。
- 授权不可用时：**只在表格标注状态**，不自动补爬。
- 调度：每周自动一次（电脑关机也能跑）+ 随时手动触发。
- 单行失败不影响其他行。

### 3.2 Out of Scope（本期明确不做）

- 绕过/破解 TikTok 验证码、打码平台、公开页探测、批量硬爬。
- 作者级「一键停掉该作者全部视频」开关（需要时对该作者各行取消追踪即可）。
- 自动投流、私信达人、内容发布。
- 完整 BI 看板、多租户、移动 App。
- 强制迁移到飞书多维表。
- 保证未授权视频也能自动更新播放量。

### 3.3 成功标准（Acceptance）

1. **已授权且有视频 ID、未取消追踪**的行：播放量等于当次 TikTok 官方接口返回值，按约定格式写入。这不是「大约对」，接口给多少就写多少。
2. 抽检用于确认实现没有写错列、没有格式化写坏，不表示产品允许 5% 写错。失败必须显式标注（过期、无 ID、接口错误），禁止把失败伪装成一个播放量。
3. 授权过期时，相关行能筛选出「已过期」，且播放量列不被乱改。
4. 电脑在计划时间关机时，当周任务仍会执行；也可随时手动再跑一次。
5. 运行成本接近 **¥0/月**。

> v1.0 写的「抽检正确率 ≥ 95%」作废。那是验收口径写松了，不是技术上限。

## 4. 现状资产（As-Is）

### 4.1 数据载体

- **飞书电子表格**（Sheets），非多维表（Bitable）。
- **单表结构**：一行 ≈ 一条合作视频；同一作者 ID 可占多行。

### 4.2 关键业务列（与自动化强相关）

| 列 | 字段名 | 说明 | 自动化角色 |
|----|--------|------|------------|
| B | ID | 达人账号标识 | 作者维度，用于挂授权状态 |
| M | 视频链接 | TikTok 视频 URL（部分单元格展示异常） | 备用，不作为唯一依据 |
| N | 视频ID | 长数字 ID | **取数主键** |
| P | 播放量(K) | 如 `322K`，带条件格式配色 | **写回目标** |
| J | 批量授权 | 如 `mass` | 现有业务标记，与 OAuth 状态分开，脚本不覆盖 J 列 |

表中头像、主页二维码、寄样、规格、封面、GMVMAX、挂车主图等运营字段，**自动化不改**。

### 4.3 规模假设

| 维度 | 量级 |
|------|------|
| 作者数 | 几十 |
| 每作者视频数 | 几十（表中为合作相关视频，非主页全量） |
| 理论行数 | 约数百～两千 |
| 每周实际更新 | 默认几乎全表；仅减去主动取消追踪、以及无视频 ID 的行 |
| 更新频率 | **每周 1 次**，外加手动 |

## 5. 产品方案

### 5.1 总体策略

```text
飞书电子表格（一张业务表）
  有视频ID 且 追踪 ≠ 否  → 本周任务
        │
        ├─ 该作者授权有效 → 拉官方播放量 → 写 P 列 + 更新时间 + 授权状态=已授权
        └─ 未授权 / 已过期 → 不改播放量 → 授权状态=未授权 或 已过期
```

原则：

1. 只走官方授权，不做验证码、不做公开页爬取。
2. 表格即配置：不追踪靠取消勾选，不另做管理后台。
3. 单行失败不中断整次任务。
4. 调度放在不依赖本机开机的地方；本机命令只负责手动补跑和开发调试。

### 5.2 调用周期：自动、关机、手动

| 方式 | 是否支持 | 电脑关机时 | 说明 |
|------|----------|------------|------|
| 每周自动 | 是 | **要跑** | 定时放在 GitHub Actions（私有仓库免费额度足够每周一次）。不把 Windows 任务计划当唯一调度 |
| 错过补跑 | 是 | 下次调度或手动 | Actions 按 cron 触发，不依赖家里电脑是否开机 |
| 手动触发 | 是 | 电脑需开机 | 本地执行一次脚本；或在 GitHub 上点 “Run workflow” |

Windows 任务计划可以「错过就开机后补跑」，但计划时刻电脑是关的，那一周就不会更新。因此**自动周更不以本机为依赖**。

周几、具体钟点仍待确认（见 §13）。默认建议：每周一 10:00（上海时间）。

### 5.3 Plan A — TikTok 授权取数

| 项 | 说明 |
|----|------|
| 方式 | TikTok for Developers 自建应用；作者 OAuth 后拉取其视频统计 |
| 适用 | 作者已授权且 token 仍有效 |
| 费用 | 个人工具量级通常免费（以官方当时政策为准） |
| 产品动作 | 发授权链接 → 作者同意 → 保存刷新凭证 → 周更拉数写表 |

### 5.4 授权不可用时

不再设爬虫或半自动抄数。行为只有一条：

| 情况 | 表格怎么写 | 播放量列 |
|------|------------|----------|
| 从未授权 | 授权状态 = `未授权` | 不改 |
| token 刷新失败 / 授权失效 | 授权状态 = `已过期` | 不改 |
| 接口临时错误（非授权问题） | 同步状态 = `失败`，失败原因写简短说明 | 不改 |

同一作者多行视频：该作者一旦过期，其下所有未取消追踪的行都标「已过期」。重新授权成功后的下一次运行改回「已授权」并恢复写播放量。

不另做消息机器人作为本期必须项。用飞书筛选「授权状态 = 已过期」就是待办清单。

### 5.5 飞书写入

通过飞书电子表格 API 读写单元格，不必改成多维表。

- 读：视频 ID、追踪、作者 ID、当前授权状态。
- 写：播放量(K)、更新时间、同步状态、授权状态、失败原因。
- 权限：自建应用 + 加为该表格协作者 + 电子表格读写权限。

## 6. 表结构（To-Be）

在表尾追加列，不改动现有 A–R 的业务含义。

### 6.1 新增字段

| 字段名 | 填写规则 | 说明 |
|--------|----------|------|
| 追踪 | **空 = 追踪**；只有填 `否` 才跳过 | 默认全跟。不要求把每行预先填「是」 |
| 授权状态 | 脚本写 | `未授权` / `已授权` / `已过期` |
| 更新时间 | 脚本写 | 仅成功写回播放量时更新 |
| 同步状态 | 脚本写 | `成功` / `跳过` / `失败` |
| 失败原因 | 脚本写 | 无视频ID、已过期、接口错误等；成功时可清空 |
| 上次播放量(K) | 脚本写，P1 | 成功更新前把旧 P 列拷到这里，便于看周增量 |

### 6.2 「追踪」是什么意思

只做**视频这一行**的开关，没有作者级开关。

- 表里每一行代表一条视频。
- 默认都更新。
- 某条不想跟了：把该行「追踪」改成 `否`。
- 某个作者整个人不想跟：把他名下每一行改成 `否`（行数不多，接受这个操作成本）。

v1.0 写的「作者级 + 视频级」是多设计了一层总开关，**本期取消**。

无视频 ID 的行无论追踪列如何，都跳过，同步状态写「跳过」，原因写「无视频ID」。

### 6.3 播放量格式

- 成功写回时保持现表风格：`322K` 这种字符串，避免打乱条件格式。
- 不足 1000 的展示规则仍待确认（§13）。在确认前：不足 1000 写整数（如 `860`），≥1000 写整数 K（如 `322K`，四舍五入到 K）。

### 6.4 主键

- 主键是 N 列「视频ID」。
- 链接列异常不影响取数；无视频 ID 则不更新。

## 9. 技术方案要点

| 模块 | 建议 |
|------|------|
| 语言 | Python |
| 飞书 | Sheets 读写 API |
| TikTok | Developer 应用 + OAuth + 视频统计接口（以审核通过的权限为准） |
| 自动调度 | GitHub Actions `schedule` + `workflow_dispatch`（手动） |
| 本地手动 | `python -m tikview sync`（名称实施时再定） |
| 配置 | 环境变量 + 列名映射（按表头名找列，不写死字母，避免插列错位） |

一次运行：

1. 读表，校验表头。
2. 选出有视频 ID 且追踪 ≠ `否` 的行，按作者分组。
3. 授权有效：拉播放量，格式化，写 P 列与状态。
4. 授权无效：只写授权状态，不动 P 列。
5. 日志输出计数。

## 11. 风险

| 风险 | 对策 |
|------|------|
| TikTok 应用审核或权限不够 | 并行申请；M1 不依赖 TikTok，可先打通飞书 |

| Actions 免费分钟用尽 | 每周一次远低于额度；若用尽再改调度 |
